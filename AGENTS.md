# Crate Bell: rules for coding agents

Chrome extension (Manifest V3, WXT, TypeScript, no UI framework) that adds a "Set a sale alert" button to Discogs and guides the user through Discogs' own alert page. Read `docs/spec.md` before changing behaviour.

## Commands

- `pnpm install` then `pnpm dev` (opens Chrome with the extension).
- `pnpm check` = lint + typecheck + unit tests. Run it before every commit.
- `pnpm build && pnpm test:e2e` for end-to-end tests (set `CHROME_PATH` if Playwright's Chromium is not installed).
- Translations: edit `locales/*.json`, never `public/_locales` (generated by `pnpm locales`).

## Rules

- All knowledge of Discogs' pages lives in `src/lib/discogs/` (selectors, URLs, limits). Features never query Discogs' DOM directly.
- Prefer ids, `data-test`, ARIA and form names over CSS classes. Discogs class names end in a generated hash: match the prefix only.
- When Discogs changes, update `docs/discovery.md` and the fixtures in `tests/fixtures/` in the same change.
- Never click "Save" on Discogs for the user, never call Discogs' private APIs, never send data anywhere but discogs.com and api.discogs.com.
- No `innerHTML` with page or user content. Text goes through `textContent` (see `src/lib/ui/dom.ts`).
- Every user-facing string goes through `t()` and exists in en, fr and de. Copy follows the Highlighter voice: second person, sentence case, no exclamation marks, no emoji, no em dash.
- UI follows the Highlighter design system tokens in `src/assets/highlighter.css`. Do not add colours.
- Keep permissions to `storage` and `https://www.discogs.com/*`. Adding one needs an ADR in `docs/decisions/`.
- Conventional commits (`feat:`, `fix:`, `docs:`, `test:`, `chore:`). Small pull requests.
